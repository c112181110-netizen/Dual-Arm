# B→C 驗證紀錄（2026-10-22）

目前結果：4 個 ROS 套件建置成功，41 項單元測試通過，14 種 B→C 整合情境通過；新增視覺介面後的既有 A→B 完整回歸亦通過。

整合測試使用 ROS 2 Jazzy、真正 MoveIt、原專案 service 型別的合成視覺回覆與理想馬達模擬；沒有開啟實體序列埠，未測實體馬達、吸盤或相機辨識。每項 B→C 情境均驗證重啟後保存 FULL/FAULT 與占用。

| 情境 | 驗證內容 | 結果 |
|---|---|---|
| `eight` | 1→8、拒絕第九件、滿格重啟保存 | 通過 |
| `cancel` | 取物確認中取消，保留 B 鎖與不確定持物 | 通過 |
| `release_failure` | 釋放失敗不提交占用 | 通過 |
| `verify_failure` | 人工格位複核失敗不提交占用 | 通過 |
| `estop` | 急停鎖存，拒絕續跑 | 通過 |
| `safety_loss` | 手臂一安全條件失效 | 通過 |
| `stale_safety` | 安全心跳逾時 | 通過 |
| `blocked_b` | B 有其他手臂，不進場 | 通過 |
| `count_failure` | 全景 C 計數未增加 | 通過 |
| `collision` | 碰撞模型使目標無可用 IK | 通過 |
| `wrong_slot` | 放入錯格，即使總數正確仍拒絕 | 通過 |
| `grid_failure` | 手眼相機格位服務回報失敗 | 通過 |
| `grid_mismatch` | 影像座標與固定校正座標不符 | 通過 |
| `recovery` | 清臺復歸、舊 token 拒絕、無自動動作 | 通過 |

八格流程完成後 occupancy 為八個 true、holding=empty、b_locked=false，拒絕第九次 B_READY；正常流程有 32 次一次性人工確認，舊碼／重複碼均被拒絕。格位驗證除全景總數外，實際呼叫 GetGridState 與 VerifyPlace 的模擬服務。

未校正的預設 hardware 配置已確認在啟動任何控制節點前被拒絕。硬體模板的幾何、關節限位與誤差欄位使用無效佔位值，必須以量測資料替換；不能只改校正旗標。

復歸測試模擬釋放失敗及程序重啟，再清臺、提供新 recovery token，確認回到 IDLE 且八格紀錄清空。它驗證了 MoveIt 場景已經清空時也能安全復歸，沒有發出復歸動作。

可重現指令、配置欄位與介面見 [B→C 使用與對接](B到C使用與對接.md)。詳細結果摘要與原始測試報告位置見 [JSON 紀錄](B到C驗證結果.json)。原始詳細日誌在 /tmp，可能隨系統清理而消失，本資料夾保留結果摘要。
