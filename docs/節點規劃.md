# 雙手臂最終節點規劃與階段邊界

更新：已新增獨立 B→C 測試器、八格紀錄與安全心跳，見 [B→C 使用與對接](B到C使用與對接.md)。下表保留第一階段與最終雙臂整合的比較。

依據[全流程圖](../詢問圖片/全流程圖.webp)與[工作區圖](../詢問圖片/工作區圖.webp)：A 區物品 XY 隨機、取物高度固定；手臂 1 把物品放在固定 B 座標；手臂 2 從 B 取物放到 C 區八個固定格。預設物品是一片小圓片，整批維持同一高度。視覺端排序策略將改動，ROS 主控只使用服務回覆，不依賴其內部排序。

| 元件 | 第一階段 | 最終規劃 |
| --- | --- | --- |
| `task_coordinator` | 手臂 1 A→B 狀態機、B 區鎖、故障日誌 | 單一協調器管理兩支手臂、B 區互斥與 C 格狀態；不能由兩個獨立主控各自決定進 B |
| `move_group` | 手臂 1 MoveIt IK、碰撞檢查、路徑規劃與執行 | 雙手臂各自規劃群組；B 區與共享場景由同一協調器授權 |
| `cm530_bridge` | 四軸量測 `/joint_states`、`/arm1_controller/follow_joint_trajectory` | 增加手臂 2 的量測與軌跡執行；每支手臂個別校正與狀態 |
| `robot_state_publisher` | 手臂 1 URDF 與座標轉換 | 雙手臂與共同世界座標；實測兩底座相對位置 |
| 視覺端（外部） | 提供 A 取物目標與 A/B 區狀態 service | 增加 C 八格占用與 B→C 所需目標服務；介面需與視覺端共同確認 |
| ESP32／吸盤（外部） | PlatformIO Home 人工操作與回報 | 若日後有可用通訊協定，再以獨立吸盤節點取代人工確認；目前無此節點 |

## 已實作的服務與狀態

| 介面 | 用途 |
| --- | --- |
| `/vision/env/get_zone_state` (`vision_interfaces/srv/GetZoneState`) | 查 A、B 物件存在與 B 手臂清空；`success=false` 時不可採信 |
| `/vision/arm1/get_pick_target` (`vision_interfaces/srv/GetPickTarget`) | Home_A 下索取 A 區目標，`peek_only=true`；XYZ 為手臂 1 基座座標、公尺 |
| `/arm1/start`、`/arm1/cancel` (`std_srvs/srv/Trigger`) | 開始單次搬運／取消目前工作 |
| `/arm1/confirm`、`/arm1/recover` (`dual_arm_interfaces/srv/ConfirmStep`) | 一次性 token 的吸盤確認／故障復原確認 |
| `/arm1/status` (`std_msgs/msg/String` JSON) | 工作狀態、`holding`、`b_locked`、待確認 token、故障訊息 |
| `/cm530/arm1/enable` (`std_srvs/srv/Trigger`) | 真實設備在檢查後明確啟用扭力 |
| `/arm1_controller/follow_joint_trajectory` (`control_msgs/action/FollowJointTrajectory`) | MoveIt 到 CM530 的軌跡執行介面 |

手臂 1 流程：`INITIALIZING` → `ARM1_STATE0_WAIT_A` → `ARM1_STATE0_QUERY_TARGET` → `ARM1_STATE1_APPROACH_A` → `ARM1_STATE1_DESCEND_A` → `ARM1_STATE1_WAIT_SUCTION_ON` → `ARM1_STATE1_LIFT_A` → `ARM1_STATE1_HOME_HOLDING` → `ARM1_STATE1_WAIT_B` → `ARM1_STATE2_B_RESERVED` → `ARM1_STATE2_APPROACH_B` → `ARM1_STATE2_DESCEND_B` → `ARM1_STATE2_WAIT_SUCTION_OFF` → `ARM1_STATE3_LIFT_B` → `ARM1_STATE3_HOME` → `ARM1_STATE3_VERIFY_B` → `SUCCEEDED`。過程另有 MoveIt 的附掛／卸除圓片碰撞物件步驟。任何未確認的吸放、視覺失敗、超界、規劃或執行失敗都進 `FAULT`，B 鎖不會在不確定物件位置時自動釋放。

## 第二階段接線原則

手臂 2 只在 C 有可用格、B 有物件且 B 無手臂時請求 B 鎖；鎖由同一協調器授予。它從固定 B 取物、回 Home_C，確認 B 區清空且手臂離開後釋放 B 鎖，才前往選定的 C 格。C 格使用八個固定姿態；獨立 B→C 已實作選格與占用保存，現在沿用原始三相機專案的 GetGridState／VerifyPlace 逐格驗證，另保留人工複核；目前程式沒有假設視覺端現有排序永遠適用。手臂 1 與手臂 2 的同步除了軟體鎖，也必須使用現場區域觀測與規劃場景，任一狀態不明就暫停。

目前已有手臂二執行節點、示範模型與八格配置，但尚無量測完成的手臂二 URDF、Home_C 校正、實機 C 八格座標、視覺 C 格服務的實機驗收或吸盤自動控制。這些屬後續整合，不應把目前的模擬通過解讀為實體雙手臂已驗證。
